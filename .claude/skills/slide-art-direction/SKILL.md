# Slide Art Direction

This skill is for presentation slides, not web application UI.

The slide is a stage, not a dashboard.

## Core principle

Every slide should have one obvious visual focus.

Do not begin by asking:
"How should I arrange all the information?"

Begin by asking:
"What should the audience notice first?"

Then decide what can disappear, fade back, move to notes, or be delayed.

## Slides are not webpages

Avoid importing web UI habits into slides.

Do not default to:
- cards
- containers
- dashboard grids
- repeated panels
- badges
- persistent navigation-like rails
- evenly distributed information blocks
- decorative UI chrome

Use these only when they genuinely communicate structure.

## Composition

Prefer compositions with a dominant element.

Examples:
- one huge byte sequence
- one code line
- one diagram
- one number
- one transformation
- one question
- one visual contradiction

Secondary material should support the focal point, not compete with it.

## Visual rhythm

A deck should not look like the same page template repeated.

Vary:
- scale
- density
- alignment
- whitespace
- use of code
- use of diagrams
- full-bleed vs contained layouts

Keep the visual language coherent without keeping the composition identical.

## Technical material as design material

For technical talks, the technical object itself is often the strongest visual.

Prefer:
- actual bytes
- actual code
- memory spans
- pointers
- arrows
- wire layouts
- compiler/runtime boundaries
- real output

over generic decorative graphics.

## Restraint

Do not add visual elements just to make a slide feel designed.

Every line, rule, color, bracket, ruler, label, or mark must communicate:
- sequence
- quantity
- grouping
- boundary
- direction
- emphasis
- contrast

If it communicates nothing, remove it.

## Anti-AI check

Before approving a slide, ask:

- Could this exact composition appear in an unrelated AI-generated deck?
- Is the slide visually memorable for its subject, or just polished?
- Did I create a layout because it serves the content, or because it looks modern?
- Is the technical object itself visible and interesting enough?
- Did I repeat a design pattern merely because it already exists elsewhere in the deck?

If the answers expose generic design behavior, redesign the slide.

## Success criterion

A viewer should feel that the deck was deliberately designed around this exact subject.

Not merely styled.

Designed.
